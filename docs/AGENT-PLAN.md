## 目标与边界

开发工程以本 checkout 为准，origin 为 `https://github.com/sumingwang233/research-desk.git`。现有 0.3.3 安装版/便携版先发布为 prerelease，不运行测试或重打包。保留用户已有源码修改与旧 D 盘 daemon 工程，不覆盖安装副本或真实研究资料。

后续先恢复科研资料到证据输出的闭环：用户主动导入的 PDF/Markdown/TXT、合法开放获取全文、按页或段落取证、引用定位、综述/研究方案及授权后保存笔记。沿用现有 pi-ai 自有 API/本机模型能力，不依赖 ClawsGO 模型服务；扫描件无文本时明确说明，首批不加入 OCR、任意终端执行或全盘索引。

Codex 为整合和验收负责人。当前没有批准向云端 worker 传输材料；如需 DSH Go，只能在说明任务包、第一方源码范围和独立 worktree 后取得对应批准。原 ClawsGO 源码、运行捕获、账号资料及本地论文不发给 worker，也不上传公共仓库。最多两个 worker；本地 GPU worker 最多一个，不与其他 GPU 工作争用。并行写入必须隔离 worktree，并先固定接口；仓库发布、ClawsGO 实例和资料存储均由 Codex 单独操作。

## 接口与验收方向

现有项目、来源、任务、SSE、笔记权限及 [S1] 引用继续可用。全文作为来源的可选附件，不把元数据标成已读全文；导入失败不能留下「已就绪」记录。模型只读取当前项目明确导入的资料片段，返回可定位页码/段落和来源。引用超出实际可用资料时显示未核验，不能伪造锚点。

开放全文仅使用明确开放接口，并记录可核对的来源与许可；获取失败保留元数据并允许本地导入，不绕过付费墙或使用 ClawsGO token。实现前固定接口和存储契约；优先复用现有 pdf.js 与平台解析能力。必要依赖变更须另说明，避免全局安装。

## 检查点与恢复

先完成 P1/P2 再开展动态分析与功能修改。P1 以独立本地源码提交保留现有改动；只做 fast-forward 推送，新建标签，不 force push。Release 先建草稿，资产传完后再公开为 prerelease，失败则保留草稿和准确状态，不重复创建。

ClawsGO 登录由用户操作；不读取密码、令牌、真实个人资料目录，也不运行闭源模型任务或可能扣费的操作。若正常观察需要这些额外权限，停在该功能并记录未知。隔离实例由本任务拥有，退出时只清理自有进程，保留证据和可恢复资料。

新功能测试按用户选择保留但不执行；不据静态图或历史验收记录宣称通过。0.3.3 资产保持不变；后续功能提交可通过 Git 逐项撤回，数据扩展保持向后兼容，不用真实用户数据做迁移演练。
